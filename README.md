# 园区总表累计读数 → 月度用量发布平台

把园区总表的**累计 kWh 读数 CSV** 整理成月度数仓可用的**用量明细与月合计**的
FastAPI + SQLite 网页应用，支持补传重发、整批拒收与不可变版本发布。

## 业务规则实现

| 需求 | 实现 |
| --- | --- |
| 同刻同内容重传不重复入库 | `(ts, period_no)` 唯一；累计值相同则幂等跳过并计数 |
| 同刻异内容 | 整批回滚拒收，库内读数不变，批次表留拒收记录 |
| 同周期读数倒退 | 合并库内+本批按时间排序逐对校验，发现倒退整批拒收 |
| 仅相邻同周期算差额 | 相邻两次读数 `period_no` 相同才计算 `后笔-前笔`；换表跨周期跳过、不估算 |
| 差额归属月份 | 归入**后笔读数所在 UTC 月** |
| 两月一次发布 | 页面选择相邻两个 UTC 月，一个事务生成明细 + 月合计新版本 |
| 保留旧版 | 版本与明细均不可变，历史版本永久保留并提供明细/合计 CSV 下载 |
| 迟到补传交错 | 发布在 `BEGIN IMMEDIATE` 事务内对**当前全部读数**快照计算并固化 SHA-256 状态指纹，同一版本的两个月必然来自同一读数状态；旧版内容不变 |
| 上传失败不改读数 | 整批事务，任何校验失败都 rollback |
| 发布失败不留新版本 | 版本头、明细、合计同一事务，失败 rollback（含故障注入自测） |

## 超功率异常核查

页面 `/anomalies` 供电网采集质控员找出“未倒退但超过电表额定功率”的读数区间：

| 需求 | 实现 |
| --- | --- |
| 设置每小时最大 kWh | 阈值只追加为 `power_threshold_versions` 版本；非数字、0、负数、NaN/inf 直接拒绝，不触碰任何数据 |
| 平均功率 | 按 UTC 时间排序，仅**相邻且同周期**读数成区间；`(后笔累计 − 前笔累计) / 时差(小时)`，跨周期不估算 |
| 超限形成待复测记录 | 平均功率**严格大于**阈值才记录；记录快照两端读数（id/UTC 时间/周期号/累计值）、时差、用量、平均功率与当时阈值 |
| 标记已核实 | 记录状态 `pending → verified`，保留核实时间与备注；重复核实幂等 |
| 补传拆开区间 | 上传事务内按现行阈值补齐新形成的超限区间；旧记录两端读数、阈值、核实结论原样保留 |
| 阈值变更 | 新建阈值版本并重算；旧记录只作历史留档，不会套用到新阈值/新区间 |
| 过期结论不冒充当前 | 页面每次都用**当前读数**重算相邻区间、用**现行阈值版本**逐条匹配：只有“区间仍相邻 + 阈值版本为现行 + 仍超限”才计入当前待办/当前已核实，其余进入历史留档并注明过期原因；核实接口在 `BEGIN IMMEDIATE` 内重新校验，过期直接 409 |
| 无效设置/写入失败 | 阈值校验在事务前完成；阈值、记录、核实状态均在事务内写入，故障注入验证整笔回滚，旧记录与读数不变 |
| 交错一致 | 上传、改阈值、核实共用 `BEGIN IMMEDIATE` 串行化；页面的阈值/读数/记录读取包在同一只读事务快照中 |

故障注入开关（仅自测）：`ENABLE_FAULT_INJECTION=1` 时，向
`/anomalies/threshold` 或 `/anomalies/{id}/verify` 发送
`X-Fail-Anomaly-Write: 1` 可在提交前模拟写入失败。

## CSV 格式

UTF-8 编码，三列（表头中英文均可，顺序不限）：

- UTC 时间：`utc_time` / `ts`，必须带时区，如 `2026-01-01T00:00:00Z`
- 表计周期号：`period_no`，整数
- 累计 kWh：`cumulative_kwh`，数值

示例见 `examples/sample_readings.csv`。

## 启动（Docker Compose）

```bash
docker compose up --build -d
# 打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `energy_data`（容器内 `/data/energy.db`）。

## 本地开发 / 自测

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/uvicorn app.web:app --reload
```

## 页面

- `/` 概览（读数/批次/版本统计）
- `/upload` 上传 CSV、查看批次接受/拒收记录
- `/readings` 当前读数与差额预览、读数状态指纹
- `/anomalies` 异常核查：设置每小时最大 kWh、查看待复测/已核实/历史留档、标记已核实
- `/publish` 选择相邻两个 UTC 月发布新版本
- `/versions` 历史版本（指纹是否匹配当前读数一目了然）
- `/versions/{id}` 版本明细、月合计与 CSV 下载

## 自测要点

`tests/` 覆盖：幂等重传、异内容拒收、读数倒退拒收、跨周期不估算、
月界差额归属、迟到补传同时改变两个月、补传与发布交错的版本一致性、
发布故障注入回滚（不留新版本）、旧版不可变；以及异常核查的阈值校验、
超限边界、补传拆区间后旧核实结论转为历史、阈值变更后旧结论不可核实、
重复保存阈值幂等、阈值/核实写入故障回滚、补传×改阈值×核实三线程交错。

`examples/sample_power_spike.csv` 含一个 2 小时 +120 kWh（60 kWh/h）的
超限区间，可配合阈值 `10` 手工验证。
